# Wawity Ports

🇬🇧 English version: [README.md](./README.md)

**Wawity Ports** — Windows-утилита для открытых портов: входящие правила Windows Firewall и проброс на роутере через UPnP, PCP или NAT-PMP, с автопродлением аренды и проверкой реальной доступности из интернета. Портативный EXE без установщика — часть экосистемы Wawity ([wawity.lol](https://wawity.lol)).

## Запуск

Готовый файл: `src-tauri/target/release/wawity-ports.exe`.

Запустите EXE и подтвердите запрос прав администратора. Требуется Windows 10/11 с Microsoft Edge WebView2 Runtime. Приложение не устанавливает WebView2 автоматически. Храните EXE в доступной для записи папке: рядом создаётся `wawity-ports-state.json` для учёта пробросов. При переносе переносите этот файл вместе с EXE.

## Использование

1. Укажите порты, например `25565`, `80,443` или `8000-8005` (до 32 уникальных портов).
2. Выберите TCP, UDP или оба протокола.
3. Оставьте «Проброс на роутере» и «Поддерживать доступ», если нужен автоматический проброс с продлением.
4. Нажмите «Открыть порты». Результат Windows и роутера отображается отдельно; подробные системные сообщения могут быть на английском.
5. Нажмите «Удалить» у правила для удаления правила Windows и принадлежащего приложению проброса.

По умолчанию входящие подключения разрешаются только в частных и доменных сетях. Публичные сети включаются отдельным переключателем с подтверждением. Не открывайте ненужные порты: это увеличивает доступность служб для других устройств.

Программа не отключает брандмауэр и не изменяет чужие правила или пробросы. Закрытие окна не удаляет правила. Правила Windows постоянные. При открытии приложение само выбирает поддерживаемый способ проброса: сохранённый ранее, затем UPnP, PCP и, только с отдельным согласием, NAT-PMP. После неоднозначного ответа роутера повторная попытка другим способом не выполняется, чтобы не создать лишний проброс.

## Аренда и автопродление

Проброс на роутере всегда запрашивается на один час: постоянные пробросы не создаются. Если включено «Поддерживать доступ», приложение продлевает аренду примерно с середины срока, пока приложение запущено. Продление приостанавливается, когда правило Windows отсутствует, состояние роутера изменилось, компьютер вышел из сна со сменой сети или аренда оказалась слишком короткой. В таблице правил видно способ (`UPnP`, `PCP`, `NAT-PMP`), оставшееся время и состояние продления. Кнопка с круговой стрелкой включает и выключает продление для отдельного правила. Закрытие приложения или выключение компьютера останавливает продление; после истечения аренды проброс исчезает на стороне роутера.

NAT-PMP не позволяет проверить владельца записи, поэтому он включается только отдельным согласием в «Диагностике сети» и может заменить запись другой программы на том же внутреннем порту этого компьютера. По умолчанию используются UPnP и PCP.

Успешное создание правила не доказывает доступность из интернета. Для этого нужен запущенный сервер, поддержка UPnP, подходящая схема NAT и разрешение провайдера. CGNAT, двойной NAT, запреты провайдера и блокирующие правила Windows могут мешать доступу.

## Диагностика сети

Раздел «Диагностика сети» показывает физический LAN-адрес и шлюз, глобальные IPv6-адреса (без открытия IPv6-firewall) и фактические ответы шлюза по UPnP, PCP и NAT-PMP. Отсутствие ответа означает «не подтверждено», а не «не поддерживается». Диагностика ничего не создаёт и не удаляет. Через 20 секунд после открытия главного экрана приложение обновляет таблицу правил, чтобы показывать актуальное состояние автопродления.

## Диагностика и лог

Раздел «Проверка портов» проверяет до 8 портов: слушающие TCP-серверы и UDP-сокеты с адресами привязки, собственные правила Windows и сохранённые пробросы. После открытия выполняется автоматическая локальная проверка, без внешних запросов. Если задано больше 8 портов, автоматическая диагностика пропускается с объяснением.

Внешняя TCP-проверка включается отдельно и требует подтверждения: IP роутера и выбранные порты передаются сервису check-host.net и его узлам. Это не проверка через NAT loopback с того же компьютера. При непубличном IP/CGNAT тест пропускается. Ошибки и таймауты сервиса не выдаются за доказательство закрытого порта. Для UDP нужен ответ конкретного приложения.

В разделе проверки остаётся итог для каждого порта и протокола со временем проверки: «Доступен извне», «Нет локальной программы», «Только на этом компьютере», «Найден локально», «UDP не подтверждён», «Доступ извне не подтверждён» или «Результат неизвестен». Несколько итогов переключаются кнопками. Внешний тест TCP выбран по умолчанию, но запрос отправляется только после подтверждения. Положительный TCP-тест подтверждает подключение к публичному IP:порту, а не принадлежность сервиса нужной программе. После автоматической локальной проверки итог тоже доступен в этом разделе.

## Временный тестовый сервер

Включите «Временный TCP-сервер», выберите ровно один свободный порт и подтвердите запуск с внешней проверкой. Сначала создайте нужное правило/проброс на главной странице: тест сам их не создаёт. Режим недоступен для UDP-only и не заменяет существующий сервис.

Диагностический сервер слушает только выбранный физический IPv4 LAN-адрес, работает до 70 секунд (включая одну повторную внешнюю попытку) или 64 подключений и автоматически закрывается после проверки, ошибки или истечения срока. Он не читает клиентские данные, не отправляет содержимое и не выполняет команды. Принятые соединения сразу закрываются.

Итог «Тестовый сервер достигнут извне» требует успешного внешнего TCP-теста и совпадения публичного IP проверяющего узла, времени и локального endpoint с принятым соединением. Без совпадения показывается «Тестовый доступ не подтверждён», даже если публичный порт где-то ответил. Это корреляция, не криптографический challenge. После теста сервер остановлен: для дальнейшей работы запустите Minecraft или вашу программу.

Результаты автоматически сохраняются рядом с EXE в `wawity-ports.log`; при достижении 1 МБ предыдущий лог ротируется. Кнопка «Скопировать» копирует полный результат, а «Открыть лог» открывает файл в Блокноте. Нижнее окно скрывается через 15 секунд, таймер приостанавливается при наведении или фокусе; последний результат можно открыть из сайдбара.

Для UPnP используется только физический LAN-интерфейс: явно выбирается интерфейс multicast и исходный IP HTTP-запросов. Новые записи сохраняют проверенные адреса UPnP-службы для удаления без повторного SSDP-поиска. Для старых записей без этих адресов по-прежнему требуется обнаружение. Приложение не отключает VPN, kill switch, сетевые адаптеры и защитные правила. Если защита VPN блокирует LAN, привязка к интерфейсу сама по себе её не обходит.

## Сборка без установщика

Нужны Node.js, Rust MSVC и Visual Studio C++ Build Tools.

```powershell
npm install
npm run build:portable
```

Frontend встраивается в EXE. NSIS/MSI не создаются. Для просмотра UI в браузере: `npm run dev`; системные операции в этом режиме отключены.

## Язык интерфейса

Интерфейс переведён на английский (по умолчанию) и русский. Переключатель — на странице «О проекте», выбор сохраняется между запусками. Заголовки и описания итогов проверки, а также системные сообщения приходят из Rust-бэкенда и остаются на русском; английские тексты вердиктов бэкенда запланированы на следующий релиз.

## Телеметрия (бета)

На время публичной беты телеметрия обязательна: передаются только два события — успешные открытия портов и ошибки. Без IP, портов и содержимого трафика. Она нужна, чтобы находить сбои на чужих прошивках, и отправляется через тот же relay, что у клиента Wawity. После беты станет отключаемой.

## Проверки

```powershell
$env:WAWITY_PORTS_TEST_MODE='1'
cargo test --manifest-path src-tauri/Cargo.toml
```

Переменная позволяет запускать debug-тесты без UAC; release всегда запрашивает права администратора. Тесты парсера не изменяют сеть или брандмауэр.

Проверено на реальном роутере TP-Link EC220-G5 (AC1200, веб-интерфейс прошивки v2019+). В тесты входит реальное сквозное открытие порта: доступность снаружи подтверждалась из 4 внешних регионов.
